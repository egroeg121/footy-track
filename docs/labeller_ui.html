Overview

The labeller is a Streamlit app for producing per-frame bounding-box labels across a video clip. A YOLO detector seeds the first frame automatically; you correct those seeds, then SAM3 propagates them through the whole clip in a background thread. You can pause at any time, scrub to a frame, fix the boxes, and restart propagation from that frame forward.

Launch with:

uv run streamlit run src/footy_track/labeller/app.py

Typical workflow

  1. Enter a video path in the sidebar. Surrounding quotes are stripped automatically (e.g. a shell-copied '…/clip.mp4' works).
  2. Auto-seed runs once on load (when “Auto-seed on load” is ticked): YOLO detects objects on frame 0, applies NMS, and prefills the canvas with editable boxes. A spinner shows while it runs.
  3. Correct the seeds: drag/resize/delete boxes in Edit mode, draw missing ones in Draw new mode, change a box’s class from the right-hand panel, or remove it with ✕. There is no “submit” step — the canvas is read live.
  4. Press ▶️ Run. The boxes currently on the canvas are used as-is; SAM3 propagates them through the clip in a background thread and the main window shows each completed frame live.
  5. Pause & correct whenever a track drifts: scrub to a frame, fix the boxes, then Restart from frame N — earlier frames are kept, propagation resumes from N.
  6. Preview & export: scrub completed frames and save the labels as JSON.

The three main-window modes

SEEDING

No run in progress. Editable canvas on frame 0, prefilled with the YOLO seeds (or whatever you’ve drawn). This is where you prepare the boxes before running.

RUNNING

SAM3 is propagating. The window shows the latest completed frame with boxes (read-only), auto-refreshing roughly once per second as new frames finish.

PAUSED

Editable canvas on the selected completed frame. A slider + Prev/Next let you scrub; edits feed Restart from frame N.

Box editing & class colours

Each box’s class is carried by its stroke colour, so the label survives moving and resizing. Newly drawn boxes take the sidebar’s Class to draw. Reassigning a class from the side panel recolours the box.

Known limitation. While seeding, the per-object class dropdown and ✕ edit the committed object set, whereas drag/resize lives in the canvas until you Run. If you reposition a box and then change its class in the side panel, the canvas re-prefills from the committed set and that un-run drag is reverted. Do canvas geometry edits and side-panel class edits, then Run (which reads the canvas).
Performance note. The first SAM3 run JIT-compiles its kernels (cached under ~/.cache/torch_inductor_sam3), so the very first frame is slow; subsequent runs are fast. Pause only after at least one frame has completed, otherwise there is nothing to correct yet.
