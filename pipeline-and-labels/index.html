    Best pipeline and label needs¶

    Research of 2026-11-08 against main @ 26d2506. Evidence tags: [V] verified against code, data or run logs; [H] stated only in <storage>/tools/HANDOFF.md (2026-08-28) or a doc, not re-checked; [I] inference. Context: Architecture, Datasets and labels, TODO list.

    Summary¶

    • The best measured ball detector is RT-DETR-L trained at 1920 on Roboflow v11: ball mAP50 0.665, recall 0.591 on v11-val [V]. The older ".221 / .209" quoted next to it was yolo11n on v11 (xeval.log); it was pasted next to the RT-DETR path by commit 24229bb (2026-08-29). The comment in detectors/ultralytics.py and the docs now say so.
    • The number is not a multi-match estimate: 156 of the 211 val balls (74%) come from one 10-second clip (arsenal_example) [V]. The production machine labels were made at imgsz 1280 while the checkpoint was trained at 1920 [V].
    • No ball tracker exists in code. Misses are dominated by long blind spells [H], so the next gains are a tracker for precision and diversity of labels, not more frames from the same clips.
    • Four label-pipeline bugs (T-01 to T-04) will corrupt the next training export; fix them before any retrain.

    Boxes at 0.7 or more are near-certain, 0.6-0.7 mostly right, below 0.6 mostly wrong. A low-confidence second pass must therefore rely on motion gating. Human-checked vittrack ball boxes are about 97% right (81 verdicts: 71 ball, 6 corrected, 2 not_ball, 2 unsure).

    Is the benchmark trustworthy?¶

    Partly. The instance count is reasonable and val clips are disjoint from train at clip level [V], but 74% of val balls are one clip, so HANDOFF's "independent" confirmation (arsenal_example 0.585 against val 0.591) is the same clip. The v11 test split (268 images, 243 balls) has never been evaluated. Cross-match generalisation is unmeasured. Unverified: whether arsenal_example overlaps a Man City training clip in time.

    2. Target pipeline¶

    1. Per-frame RT-DETR-L at 1280 (keep it).
    2. An inference-only ball association layer over the stored conf 0.1 or more detections: ByteTrack/BoT-SORT-style low-confidence second pass, Kalman with high process noise and camera-motion compensation, gap interpolation.
    3. Later, a temporal detector: prior-conditioned RT-DETR (CenterTrack, bead ft-1zq), a heatmap over a frame stack (TrackNetV3, WASB), or YOLOFT-style correlation. The segmenter already gives cut-free clips.

    What the data says [H + I]: misses are dominated by long blind spells (one 51-frame gap holds 70% of arsenal_example misses; only 7% fall in 1-2 frame gaps), so a t-1 prior is estimated to buy about 0.585 to 0.62 recall. The larger lever is diversity; a tracker mainly buys precision. The CenterTrack run reached epoch 11/80 before the desktop reset and no result is recorded.

    Gaps between today and the target: no committed ball eval; no ball tracker in code; the producers are outside git (training command, batch inference, candidate filter, the temporal package, which exists only in <storage>/backups/temporal_work.tgz, and the ft-1zq code, only on the desktop machine); the held-out dense GT is too narrow to see a 0.03 gain; the label-plumbing seams corrupt exports; the 1920-train versus 1280-serve mismatch is unmeasured.

    Seam ids (S1 and so on) are the rows of Architecture, section 7. Notes that do not fit in a table cell:

    • A. Unknown tags default to in_play_ball on load. The data-loss bug in the older write path was fixed in 6bcd153.
    • B. For the ball it is useless: it stays on the ball for 5% of frames (9 of 176) and Run halts at frame 1. Players propagate fine. No code in the repo writes human_checked (searched 2026-11-08), so new VitTrack output can never become tier 2. The v11 snapshot was exported on 2026-08-04, before the backfill, so its vittrack boxes went in unreviewed.
    • D. Labelling speed, measured from the verdict timestamps of 2026-09-24 and 09-25: 360 decided verdicts in 19.9 active minutes (gaps over 60 s excluded), about 3.3 s per card, 18 per minute. With a 30 s gap cap it is 2.6 s per card, so the figure is an estimate with about 25% slack, from one person on two days. How the page works is in Architecture, Ball Check.
    • E. v11 was built on 2026-08-04 from a store export. The uploader that does that exists only on unmerged branches (feat/roboflow-dataset-export, feat/roboflow-upload-script). Class ball is dead (one instance).
    • F. The run was rtdetr-l_1920_v11 on a rented 3060, 82 minutes for 97,625 frames. A ball verdict, the cheapest human signal, is thrown away.
    • H. mancity_seg104, the designated eval clip, is centre-only and has no MP4 next to it.

    The newest feature store (2026-08-04) predates the human_checked ingest fix, the Ball Check corrections and six new sidecars, so store, export and Roboflow is stale end to end (T-07).

    5. Recommendation, in order¶

    1. Fix the record. Done on this branch: the code comment and docs now cite .665 / .591 and the 74% caveat. The KB findings page still needs updating, with the maintainer's approval (T-15).
    2. One committed ball eval over the v11 test split plus held-out dense clips (arsenal_example after checking it is not a sub-span of a training clip, and mancity_seg031), at 1280 and 1920, reporting instance counts and a per-match breakdown (T-10). The 1280 half needs no GPU for the sidecar clips.
    3. ByteTrack/Kalman ball association over existing machine labels, with thresholds from the precision bands (0.7 or more near-certain; 0.6-0.7 about 0.79; below 0.6 at most 0.42). Run analyse_ball_tracker.py first to split detector misses from tracker misses (T-20).
    4. Diversity labelling on new matches (Aston Villa, Bournemouth 2nd half, Norwich) with /ball_check, holding one full match out for eval; at about 3.3 s per card, 1,000 cards is about an hour (T-13, T-21). Look at the 51-frame arsenal_example gap first.
    5. Before any retrain through the store, fix S1 to S4 (T-01 to T-04) and make the export default to tier 1/2 (T-22).
    6. Commit the missing producers and recover the ft-1zq code from the desktop machine (T-09, T-23); retrain RT-DETR-L at 1280 on v11 plus new-match labels and compare on the step 2 eval.
    7. Only then: finish ft-1zq on a rented GPU, or a heatmap/YOLOFT detector if the tracker and diversity plateau.

    Do not bother with: tuning VitTrack thresholds or SAM3 (measured dead ends), 1920 resolution or bigger GPUs (1920 is about 1280), scaling YOLO (yolo11m/l lost), RF-DETR (caps below 1280).

    6. Uncertainties¶

    • Whether arsenal_example overlaps training footage.
    • The CenterTrack result is not recorded; the HANDOFF temporal miss analysis was not reproduced.
    • The recall matching rule (centre within max(12 px, box size)).
    • The held-out GT mixes tier 1 and 2, and tier 2 is vittrack-derived (about 97% precise).
    • WSL and desktop data copies were not inspected.
    • Per-class player mAP for RT-DETR was never logged.
