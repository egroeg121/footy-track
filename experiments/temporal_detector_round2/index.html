    Round 2: does pseudo-labelled data (v11 train + filtered pseudo) change the 3ch / 5ch comparison?¶

    Branch exp/temporal-detector. Code: experiments/temporal_detector/{pseudo_filter,pseudo_audit_survivors,round2_report}.py, flow temporal-ablation/temporal-ablation ... pseudo=true exp_tag=r2 (~/code/jobs/footy_temporal.py). Builds on temporal_detector_ablation.md (v1) and temporal_pipeline_eval.md. Pseudo labels: /mnt/storage/footy_data/multiframe_pseudo_v1/ (branch exp/pseudo-labels-v1 7c53b25).

    Questions and answers¶

    Same recipe as v1 (YOLO11s, imgsz 1280, batch 4, HSV and Albumentations off, last.pt), but train = v11 train (1,034) + 1,617 filtered pseudo-labelled images, 60 epochs (v1: 100; the larger set gives 663 vs 259 iterations per epoch, so about 40k vs 26k in total), 2 seeds each: A+ (3ch, same pixels as PNG) and B+ (5ch, inflated stem). Val, test, heldout, strict and the metrics are exactly v1's, so every number compares directly with v1's A / B.

    1. Does pseudo data close the seed variance? Yes. Seed range of hit@10 (A / B, v1 -> round 2): val 0.153 / 0.081 -> 0.038 / 0.000; val clip arsenal_example 0.186 / 0.103 -> 0.051 / 0.006; test 0.013 / 0.008 -> 0.004 / 0.004; held-out 0.034 / 0.017 -> 0.000 / 0.000 (both seeds 56/117 for both arms). Ball AP50 on val at the last epoch: A_s1 0.369 vs A_s0 0.509 in v1, Ap 0.606 / 0.657 and Bp 0.624 / 0.669 now.
    2. Does it raise held-out and arsenal_example recall? It raises in-domain recall, not held-out.
    3. Test (same match and broadcast as the pseudo pool; 33 test clips share a clip with train): A+ - A +0.076 [+0.046, +0.109], B+ - B +0.065 [+0.038, +0.095] (A 0.880 -> 0.956, B 0.878 -> 0.943; RT-DETR 0.916). Candidate recall any@10 +0.055 / +0.044.
    4. val clip arsenal_example (156 balls, no train frames): A+ - A +0.221 [+0.157, +0.285] (0.375 -> 0.596), B+ - B +0.029 [-0.026, +0.083] (0.583 -> 0.612): A catches up with B (RT-DETR 0.667). Other val clips: +0.047 [-0.009, +0.123] / +0.113 [+0.047, +0.189].
    5. Held-out clips (117 balls, 11 clips, other matches / provenance than the pool; strict 84): A+ - A +0.017 [-0.004, +0.043], B+ - B +0.000 [-0.038, +0.038]; strict +0.018 / +0.000. No gain: A+ and B+ both 0.479 against RT-DETR 0.487; candidate recall any@10 stays at 0.54-0.57 (RT-DETR 0.675), i.e. the held-out misses are balls no candidate covers, and more same-match pseudo data does not fix them.
    6. Does B - A widen with more data? No, it narrows or vanishes. B+ - A+ hit@10: val +0.019 [-0.017, +0.055] (v1 +0.146), test -0.013 [-0.029, +0.002] (v1 -0.002), held-out +0.000 [-0.030, +0.030] (v1 +0.017), test+heldout -0.008 [-0.024, +0.006]. The difference of differences (B+ - A+) - (B - A) is -0.127 [-0.187, -0.067] on val, entirely arsenal_example (-0.192 [-0.266, -0.119]: v1's 5ch advantage there was a small-data effect that 3ch closes with pseudo data), and -0.011 / -0.017 (n.s.) on test / held-out. Candidate recall B+ - A+ is ~0 everywhere (test -0.004, held-out +0.026 [-0.021, +0.077]); the v1 gain for the fastest third of balls (+0.066) shrinks to +0.035 [-0.004, +0.075].
    7. Through the trajectory solver (appendix; harness B1 camera on, the 9 test clips, 170 balls): A+ 0.794 raw / 0.826 iso, B+ 0.829 / 0.844 recall@10, precision 0.99 / 0.98-0.99. B+ - A+ +0.035 [+0.009, +0.067] raw, +0.018 [0.000, +0.036] iso (v1 +0.047 / +0.029): the 5ch edge under the solver survives but did not widen. Both round-2 detectors now exceed the production RT-DETR-L (0.759) on these clips: B+ - RT-DETR +0.071 [+0.033, +0.111] raw, +0.085 [+0.047, +0.126] iso at unchanged precision (-0.005 to +0.012), ceiling 0.838 vs 0.829. On arsenal_example (all labelled frames, the labelled deviation) A+ 0.264 / 0.457, B+ 0.256 / 0.420 (raw / iso), B+ - A+ -0.009 [-0.048, +0.031] (v1 +0.071), and RT-DETR (0.540) is still well ahead (B+ - RT-DETR -0.284 raw, -0.119 iso).
    8. False positives on ball-free images (35 images of val+test+heldout, small n): top-1 conf >= 0.5: A 0.171 -> A+ 0.157, B 0.157 -> B+ 0.186; conf >= 0.7: 0.071 -> 0.114 (A+), 0.071 -> 0.143 (B+); confident wrong top-1 picks on ball frames (conf >= 0.5): 0.008 -> 0.013 (A+), 0.005 -> 0.009 (B+). A small rise at high confidence (2-3 images of 35, within noise), no sign of a crowd/kit leak at the scale visible here; RT-DETR remains the noisiest (31% at conf 0.5, 4.1% confident wrong picks).

    Reading. The pseudo data is worth about +0.07 test recall and removes seed noise for both input types, so most of v1's A-vs-B difference was a low-data / high-variance effect rather than a lasting benefit of the temporal channels. A 5ch detector keeps a small edge only after a solver ranks its candidates (+0.02 to +0.04 on the test clips) and nothing measurable on held-out clips. The filter rule (conf >= 0.45 and a conf >= 0.8 node within 25 frames) was not ablated: no run with all 759 low-conf B1 images or with the 241 + 257 dropped ones exists, so the effect of the filtering itself is not measured. Epochs differ from v1 (60 vs 100), so "round 2 vs v1" mixes data and schedule.

    Filter and data¶

    • Counts: of 2,115 pseudo images 1,617 survive: 1,000 easy (conf >= 0.8) + 356 S1 fills + 261 of 759 low-conf B1 (dropped: 241 with conf < 0.45, 257 with no conf >= 0.8 B1 node within +-25 frames). Segment ids are not in meta.jsonl, so segments were rebuilt from the provenance table (provenance_all.jsonl.gz): consecutive B1 rows with gaps <= 25 frames, so the rule reduces to "a conf >= 0.8 B1 detection within +-25 frames"; cuts inside the window are not checked.
    • Audit hit@10 of the survivors (the pseudo doc's audit pipeline: the harness' B1 re-run on the 18 GT-bearing harness clips + arsenal_example; B1 detections with conf < 0.6 on a human GT frame): all low-conf 38/50 (76%; the doc's 38/49), survivors 13/15 (86.7%) (test 3/4, dev 8/9, arsenal_example 2/2). n is tiny; S1 fills (19/20 in the doc) and easy images (138/138) are unchanged.
    • Eval overlap: zero, checked explicitly: no pseudo frame lies within +-5 frames of a v11 val/test/heldout image or in a clip with one (the pool excludes all 97 such clips), and none belongs to arsenal_example or the 9 trajectory test clips (3 of them excluded from the pool by the pseudo build). The near_v11_train_5 frames (91) are kept; near_human_gt_5 frames (52) are of pool clips that are not evaluation clips and are kept.
    • Transfer: only the 1,617 survivors (6.05 GB) went to the desktop, via S3 (new prefix exp_temporal_r2/pseudo_v1/, upload from the mini about 4 MB/s, download by presigned-URL curl, resumable); the direct mini -> desktop rsync measured 1.2-1.8 MB/s over the Wi-Fi. Sizes verified against the mini copy; presigned URL list deleted from the desktop.
    • Training cost: 2.0-2.1 h per 60-epoch run (about 2 min/epoch, GPU not shared, no crash); four runs about 8.3 h.
